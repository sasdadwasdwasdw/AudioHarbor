# Bundled components

AudioHarbor is MIT licensed. Third-party components retain their own licenses. No exclusive ownership or prohibition on reverse engineering of LGPL components is asserted. The selected FFmpeg archive ships LGPL version 3; its complete license text is installed with AudioHarbor. FFmpeg and dependency corresponding sources must accompany public distribution as described below.

- yt-dlp Windows standalone 2026.10.26: [Unlicense and bundled dependency notices](https://github.com/yt-dlp/yt-dlp/tree/2026.10.26). The official standalone includes yt-dlp-ejs. Its full THIRD_PARTY_LICENSES.txt and LICENSE are downloaded at the pinned tag and installed under `licenses/engines`.
- Deno 2.9.8: [MIT license and included third-party notices](https://github.com/denoland/deno/blob/v2.9.8/LICENSE.md), installed with the app. The full runtime is bundled, not denort.
- FFmpeg and FFprobe 8.1.3-27-g8dca1586f4: separate unmodified executables from the pinned [BtbN LGPL Windows x64 build](https://github.com/BtbN/FFmpeg-Builds/releases/tag/autobuild-2026-10-30-13-01). AudioHarbor communicates through process arguments and pipes. It does not link FFmpeg libraries into the application. This software uses FFmpeg under LGPL 2.1 or later; the selected binary's `-L`, build configuration and included license files govern linked dependencies. No GPL/nonfree variant is selected.
- Tauri: MIT/Apache-2.0; React, Zustand, Tailwind CSS, Radix UI, shadcn/ui: MIT; Lucide: ISC. Package versions are pinned by package-lock.json and Cargo.lock. Distribute their notices as appropriate with your source distribution.

`npm run engines:prepare` verifies SHA256 hashes pinned in `scripts/engines.lock.json`, copies upstream archive notices and writes the installed engine manifest. `npm run licenses:collect` also installs complete license texts from production npm and Windows Rust dependencies. The unmodified MPL-2.0 selectors 0.38.0 sources are available at https://crates.io/api/v1/crates/selectors/0.38.0/download. See the installed notices for all exact source versions. SHA256 checks protect preparation integrity; they are unrelated to Tauri updater signatures.

For public release, the distributor must assemble and host a complete corresponding source archive matching the exact FFmpeg build, including its linked dependencies, patches and build scripts. Use the upstream pinned FFmpeg commit `8dca1586f4`, the BtbN build configuration from the exact release and the library revisions used by that build. Archive the upstream build inputs rather than substituting a newer source tree. Set `FFMPEG_SOURCE_ARCHIVE_URL` and its SHA256 in GitHub Variables. The release workflow refuses to publish without this archive and attaches it alongside the MSI on the same GitHub Release. Hash verification checks integrity, not completeness: the distributor must verify correspondence before setting these variables. If exact inputs cannot be recovered, rebuild an LGPL FFmpeg distribution from retained inputs and update the engine pins.

See [FFmpeg's official license guidance](https://ffmpeg.org/legal.html) and each shipped license for source distribution obligations. Do not substitute GPL/nonfree builds without reviewing their different obligations. Engine source compliance remains a release prerequisite until a corresponding archive is supplied; local testing is available independently.
